# Архитектура V2

## Граница слоёв

1. `physics` — чистая детерминированная Java-математика, не импортирует классы Project Zomboid.
2. `PzRuntimeAccess` — единственное место, знающее имена классов/полей B42.20.4.
3. `RuntimeHooks` — владение симуляцией, состояние машины, feedback нативных сил и телеметрия.
4. `pzmod.carphysicsimproved` — маленькие ZombieBuddy-патчи и Lua API.

## Единая трансмиссия

Manual и automatic передают один и тот же `DriverInput` в `VehicleDynamics`. Manual держит запрошенную передачу; automatic выбирает её по RPM и нагрузке. Сцепление, torque curve, двигатель, сопротивление, тормоза и шины общие.

## Шины и состояние машины

Для каждого колеса читаются:

- наличие шины;
- condition;
- давление через container content/capacity;
- прокол как нулевое condition/давление;
- wheelFriction установленного предмета относительно VehicleScript.

На осях считаются отдельные grip/cornering/rolling коэффициенты. Разница лево/право создаёт увод. Состояние подвески уменьшает боковую жёсткость, тормозов — тормозную силу, двигателя — момент. Payload увеличивает массу и перенос веса.

`VehicleScript` B42 не содержит признака ведущей оси. Поэтому generic fallback — RWD, а compatibility-моды могут зарегистрировать `FRONT`, `REAR` или `ALL` через `CarPhysicsImprovedMod.setDriveLayout(fullType, layout)` без изменения JAR.

## Связь с Bullet

Vanilla продолжает lifecycle и collision/contact simulation. После `CarController.update` V2 обнуляет финальную ванильную тягу/тормоз, задаёт ограниченные физические силы через `applyCentralForceToVehicle` и yaw через `applyTorqueToVehicle`. Первые 0.75 секунды после посадки остаются ванильными. Экспериментальный наблюдатель нативных сил удалён в `0.1.1-dev`, потому что шум производных при пробуждении машины вызывал самораскачку.

Это требует обязательной runtime-калибровки: прямые силы подтверждены математически и по ABI, но стабильность исправления должна быть проверена повторным фактическим заездом.
