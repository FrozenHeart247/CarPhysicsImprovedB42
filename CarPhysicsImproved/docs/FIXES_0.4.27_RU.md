# CPI 0.4.27-dev — исправления по финальному ревью

Обновление 0.4.28: после дорожного теста пользователь сообщил о потере принятого дрифта и закрутки. Изменение №4 (перенос сцепления на per-wheel параметры) отменено, восстановлен точный участок сцепления из 0.4.26. Поэтому описанная ниже изоляция одинаковых машин **не является свойством текущей 0.4.28**. Остальные исправления сохранены; подробности в `FIXES_0.4.28_RU.md`.

Дата: 2026-09-05. Контрольная версия: 0.4.26-dev. Целевая проверенная Java ABI: установленная B42.20.4, ZombieBuddy 2.3.3.

Это исправления интеграции и расчётных ошибок, а не новая настройка автомобиля. Исторический `RELEASE_REVIEW_0.4.26_RU.md` сохранён как отчёт о предыдущей версии. DOCX не изменялся.

## Закрытые пункты ревью

| № | Исправление |
| --- | --- |
| 1 | Pedestrian/Corpse advice явно описывают аргумент столкнувшегося объекта. Реальный трансформатор установленного ZB теперь вставляет `begin` и `end` в оба метода. Сохранённые ZombieImpulse/CorpseImpulse начинают действовать. |
| 2 | Силы обычного заноса, ручника и power drift публикуются контроллером, но отправляются перед каждым 100 Hz шагом Bullet. Множитель 0.6 сохраняет бюджет прежних 60 команд/сек. Запрос ограничен сроком 250 ms, владением, collision cooldown и вертикальной скоростью; отдельная drift-клавиша не получает эти силы поверх своего yaw. |
| 3 | В основном burnout signal вместо текущего dt используется опорное 1/60 s. При одинаковом входе порог и величина эффекта больше не меняются с FPS. Тяга и traction cap не изменены. У clutch kick сохранён дополнительный путь wheelspin. |
| 4 | Больше нет записи в общий VehicleScript.wheelFriction и вызова script.toBullet. Временный множитель меняет только свежий friction-slot колеса конкретной машины перед отправкой её параметров в Bullet. Две машины одного script имеют независимые запросы. Выход, disable, смена script/водителя/владельца и истечение запроса восстанавливают свежие штатные параметры, не старое состояние шин. |
| 5 | Добавлены ранний и окончательный контроль незагруженного участка впереди/сзади: CPI не возвращает двигательную силу поверх защитного торможения. Учитываются направление движения и запрос тяги, в том числе движение накатом. Буксируемая машина не захватывается CPI-контроллером. |
| 6 | Круиз-контроль учитывает штатный isGas и throttle при отсутствии ручных команд. Shift для изменения regulator не превращается в полный газ. В ручных N/R положительный запрос cruise не подменяет выбранную передачу. |
| 7 | Enabled учитывается также для plant/obstacle impulses, windchill и дождя в салоне. При выключении входные значения сохраняются. |
| 8 | Число передних передач 1…8 соответствует заявленному машиной. Старые наборы 3/4/5 сохранены точно; для 1/2 и 6/7/8 добавлены игровые наборы без подмены на четыре передачи. Это не восстановление индивидуальных заводских передаточных чисел каждого мода. |
| 9 | Дополнительный дождь изменяет аргументы единственного штатного ClothingWetness.updateWetness. Второй полный вызов, повторно обрабатывавший пот/высыхание, удалён. Штатная последующая синхронизация влажности остаётся на месте. |
| 10 | Дополнительная фаза вращения задних колёс применяется после native readback в WorldSimulation.updateInternal. Она накапливается по времени, а не повторно на каждом подшаге с длительностью полного кадра. Искусственная запись в skidInfo удалена: датчик проскальзывания не получает собственные нарисованные значения. |
| 11 | Overall tire traction переименован в Drivetrain and slide traction / «Расчётное сцепление: тяга и занос». Подсказка описывает область действия и насыщение внутренних ограничений. Дополнительный общий множитель native cornering не вводился. |

Также уточнены подсказки: сцепление ручника относится ко всем колёсам текущей машины, а 60 секунд жизни следов — верхняя граница при лимите 900 следов. Значения Sandbox, сочетания клавиш, opacity 0.25 и lifetime 60 не сбрасывались.

## Что осталось контрольным

- На 77 760 шагах тяга, торможение, steering, сопротивление, RPM, состояние переключений и throttle 3/4/5-ступенчатых коробок точно совпали с кодом старого поставляемого JAR. Сценарии включают разные типы машины, коробки, покрытия, трейты и 30/60/120 FPS.
- Для этого golden-проверка исключает только два намеренно исправленных косметических поля burnout. Новый эталон получен запуском того же теста с **старым 0.4.26 JAR первым в classpath**, а не снят с исправленного кода: `cf07a0d009b4114c70a6e054ceeb44d3729decfce0089e59515014f1eb1da36b`.
- Классы LegacyKeyDrift, LegacyKeyDriftCommand, LegacySlideDynamics, LegacyTerrainDynamics, LegacyTireCondition и LegacyDriverTraits побайтно совпадают с контрольной сборкой. Own-body yaw gain 1.96, steering отдельной клавиши и её 100 Hz подача не перенастраивались.
- Изменение места применения сцепления всё равно требует дорожного A/B-теста: совпадение коэффициента не доказывает идентичность поведения native solver.

## Выполненные проверки

- Полный `media/src/test.ps1`: 24 Java test entry points и Lua Mod Options mock прошли. Java собирается с `--release 24`, предупреждения компилятора считаются ошибками. Runtime/интеграционные тесты загружают собранный production JAR раньше тестовых классов.
- Проверена установленная B42 ABI, включая новые методы границ карты, towing, regulator, wheel stats и ClothingWetness.
- В 14 проверяемых advice подтверждено фактическое внедрение ожидаемых вызовов настоящим трансформатором установленного ZB. Дополнительно исполняются woven-фикстуры native wheel array, смены authority и clothing update. Для дождя проверяется ровно один проход тела метода и реальное изменение scalar-аргументов, а при disable — точное сохранение аргументов.
- Per-instance grip: одновременные машины одного script, независимое восстановление, свежая база, отсутствие повторного умножения, истечение запроса и повтор восстановления после ошибки публикации.
- Fixed-step key yaw: 20…240 FPS, отпускание, контрруление, stale request, безопасность и SP/MP authority. Non-key command: одинаковый трёхсекундный бюджет при 20/30/60/120/240 FPS; физическое состояние машины в этом тесте фиксировано, это не дорожная симуляция.
- Проверены 1…8 передач, одинаковый burnout signal при одинаковых входах, final native safety command, cruise и merge дождя.
- Kahlua принял три поставляемых Lua-файла; luac и JSON-парсер также прошли. В JAR нет zombie.* replacements или тестовых классов.

## Что проверить в игре

Полный игровой запуск и выделенный сервер с двумя клиентами этим прогоном не заменяются. Рекомендуемый короткий порядок:

1. Полностью перезапустить игру. Убедиться в логе, что загружена **0.4.27-dev**, а не старый Workshop JAR.
2. Race Car: привычный разворот отдельной клавишей, отпускание и контрруление. Затем ручник и обычный power drift. Новая временная база ориентирована на прежние 60 FPS; при другом прежнем FPS сила обычного заноса может отличаться.
3. Две машины одной модели: одна в заносе/с повреждёнными шинами, другая исправна. Смена машины, выход, перезаход и выключение CPI не должны оставлять ослабленное сцепление.
4. Старт/burnout и N→1, следы и звуки при 30/60/120 FPS. Порог основного burnout теперь равен прежнему 60-FPS порогу, а не зависит от частоты кадров.
5. Cruise; ручные N/R; движение вперёд и назад; намеренно добираться до незагруженной карты не требуется — защитный путь проверен фикстурой.
6. Стекло ≤40% / отсутствующее, дождь и движение; выключить CPI и сравнить со штатной обработкой.
7. ZombieImpulse/CorpseImpulse: прежние сохранённые значения теперь реально влияют на импульсы. При малых значениях столкновения могут стать легче. Отдельный corpse bump не перенастраивался.
8. MP: передача одной машины между двумя клиентами, одинаковые модели, серверный SpeedLimit, выход/смерть водителя. Пока это не проведено, MP остаётся проверенным по коду/фикстурам, не по живой игре.

## Не смешано с багфиксом

Сохранены ограничения модели из аудита: converter-подобная ручная КПП без полного stall/clutch, общий RPM-профиль большинства машин, отсутствие определения реального FWD/AWD, порог снега, объединение потерь через минимум, прежний aerodynamic drag, контракт fixed API override. Клиентские Mod Options и дополнительные следы/эффекты не получили новый сетевой протокол. Инициализация Sandbox на dedicated server и её влияние на серверные ветки требуют отдельной MP-проверки. Полная интеграция ванильной задержки педалей от опьянения не заявляется этим исправлением cruise.
